## Conflicts

Two findings from this research materially complicate the issue/plan text's framing, without contradicting it outright. Recorded here rather than resolved, per the brief.

1. **"Minimize/restore event plumbing" (issue #25 point 2, plan Task 17: "SDL3 minimize/restore/occluded events surfaced") vs. Wayland's documented event/flag unreliability.** The issue and plan both describe the fix as event-driven ("event plumbing", "events surfaced"). Row 3's verified finding is that `SDL_EVENT_WINDOW_MINIMIZED`/`RESTORED` do not fire on a real Wayland compositor-driven minimize on this project's pinned SDL3 3.4.14 (`github.com/libsdl-org/SDL/issues/13473`, `wiki.libsdl.org/SDL3/README-wayland`), and `SDL_GetWindowFlags() & SDL_WINDOW_MINIMIZED` is equally unreliable there for the same reason. An implementation that treats "surface the events" as sufficient (matching the issue's literal wording) will silently fail to suspend presentation on a real user-initiated Wayland minimize — the exact crash/battery scenario the ticket exists to close, un-closed on one of this project's three target desktop platforms (SteamOS's Desktop Mode and any Linux Wayland session). The correct fix (row 2's recommendation: gate on the actually-queried extent, not the event) is consistent with the *spirit* of the ticket but not literally what its text describes. Not resolved here; the coordinator should decide whether the acceptance criteria should explicitly name the extent-driven design over the event-driven one issue #25's text implies.
2. **Vulkan Roadmap 2022 wasn't used to double check that Wayland's `currentExtent` sentinel behavior is universal across drivers this project targets** (RADV/Mesa on the Deck floor, NVIDIA proprietary on the dev machine). The `(0xFFFFFFFF, 0xFFFFFFFF)` sentinel claim (row 3) is corroborated by search-engine synthesis of Khronos/community sources rather than a single directly-fetched, quotable Khronos spec paragraph the way the Win32/Xcb/Xlib (0,0) case was (row 2's VUID/spec fetch succeeded directly; the Wayland-specific extension spec page was not independently fetched in this session — see Verification health). This is flagged as a lower-confidence input to the same conflict above, not a fully independent one.

## New gaps

Checked against `feature-gap-audit.md` (full file) and the registry's deferred list (`docs/superpowers/specs/2026-08-09-toolchain-platform-rhi-design.md:208-223`) before claiming novelty — both already carry FG7 (window edge states) and FG7b (exclusive fullscreen) as registered items, and both already carve out occlusion/DPI as SDK-phase. This is a platform-coverage nuance inside an already-registered item, not a new capability; flagged so the acceptance criteria (and the eventual MANUAL_VERIFICATION rows, row 16) don't silently claim "minimize works" as a blanket, all-platform statement when one of the three target platforms cannot observe it at all.
