# PRIMARY GATE — coordinator rulings (2026-08-18)

Binding companion to the 16 completeness matrices in this directory.
Each ticket's acceptance criteria = its matrix's "Proposed acceptance
criterion" column AS AMENDED by the rulings below. Where a matrix
recorded a Conflict or proposed a re-ruling, the adjudication here is
final. Matrix criteria not mentioned here are adopted verbatim.
Implementers read: their ticket body → their matrix → this file's
section for their ticket. On any contradiction, this file wins, then
the spec, then the matrix.

## Cross-cutting architectural rulings

**RC1 — Fixed-function pipeline-state axis (new spec D28).** The
#8/#23 matrices independently converged on the same hole:
`MaterialSystem::getPipeline()` hardcodes blend/cull/depth state with
no cache-key axis, and `PassSignature` explicitly disclaims carrying
it. Ruling: `MaterialRecord` gains fixed-function state (alphaMode →
blend enable + depth-write + MASK-cutoff carriage; doubleSided → cull
mode), included in the pipeline cache key; `PipelineRequest` unchanged.
alphaMode/doubleSided are NOT specialization constants — Task 16's
"specialization bits gain alphaMode/doubleSided axes" prose is
CORRECTED to match D22's own wording (they are `VkPipeline`
fixed-function state; MASK's cutoff is a per-instance uniform with an
always-present conditional discard, not a spec constant). Lands in
Task 16 (first consumer). Registered as the reusable mechanism future
fixed-function needs (wireframe, stencil) extend.

**RC2 — Per-pass depth convention & clear values (new spec D29).** The
render graph's depth clear is a process-wide 1.0 constant at two
executor sites, and `AttachmentDesc` has no clear-value field — the
scene path cannot clear reversed-Z main (0.0) and standard-Z shadow
(1.0) in one frame. Ruling: `AttachmentDesc` gains an explicit
`DepthConvention { Standard, Reversed }` on depth attachments (clear
value and the pass's expected compare direction derive from it);
executor reads it at both sites (executor.cpp:646, :1119). Lands in
**Task 22** (its real blocker — file list widened to rx_graph), tested
with a two-pass frame mixing both conventions.

**RC3 — Depth compare-op fork (matrix #23 Conflicts): option (a).**
The scene-path shadow-caster pass is a depth-only pipeline built
OUTSIDE MaterialSystem (own pipeline, D26.1 addressing per its matrix
row); `getPipeline()` serves only reversed-Z main-camera pipelines from
Stage 2 on, so its compare-op flips as one literal in Task 22 — no
compare-op cache axis is built in Phase 4. Consequence rulings:
- BLEND-partition draws are EXCLUDED from `ShadowLists` in Phase 4
  (documented + tested limitation; standard default).
- MASK casters cast their full-triangle silhouette in Phase 4 (the
  depth-only pass has no alpha test; documented limitation, revisited
  with the cascades work). Neither gated sample depends on MASK-caster
  correctness.

**RC4 — UploadTicket primitive (amends D25): timeline semaphore.** The
#28 matrix proved the reused-single-fence design structurally
incompatible with a pollable ticket (reset-while-referenced hazard,
its row 1). Ruling: one timeline semaphore owned by `Uploader`; each
`flush()` that submits GPU work signals a monotonically increasing
value; `UploadTicket = { uint64 value; uint32 ringGeneration }`;
`isComplete` = one `vkGetSemaphoreCounterValue` compare; `wait` =
`vkWaitSemaphores`. No fence pool, no reset, hazard eliminated by
construction (core Vulkan 1.2, no gating). Direct-path-only batches
(UMA/ReBAR — the Deck common case) return an already-complete ticket
(value ≤ last signaled; consistent with today's no-op flush). Ring
reclamation per the matrix's D3D12-pattern row (poll-reclaim completed
entries first; block only on the oldest ticket covering the needed
range). The overlapping-flush discrimination test (matrix row 1) is
the ticket's highest-priority gate.

**RC5 — Light channels stay COUPLED (D15 stands, recorded as
deliberate).** The #7 matrix proved Filament's channels gate lighting
only while D15 commits to Unreal's coupled model (channels gate
lighting AND shadow-casting). Ruling: coupled stands for Phase 4 — one
predictable knob for hosts while the only light is directional; the
separable split is revisited with punctual lights (techniques phase).
D15 annotated. Additionally: `RenderableDesc` gains
`castsShadows: bool = true` (Filament-precedent per-object opt-out,
one SoA bool consumed by `buildShadow`) — the channels mask is not the
only way to exclude a caster.

**RC6 — D18 amended: wall-clock STALL DETECTORS may block CI.** The
#22 matrix's two-tier resolution is adopted: 2 ms per-call main-thread
budget asserted locally and published as a trend number (never
CI-blocking, per D18); a 10 ms per-call CI assertion acts as a stall
DETECTOR — the defect class it catches (an unbounded fence wait, tens
of ms) sits an order of magnitude above runner noise, so it can block
honestly. D18's "never CI-blocking" is amended with exactly this
carve-out (detectors yes, trends no).

## Errata

**E1 (2026-08-18, found during Task 12 implementation, reviewer-confirmed):**
matrix-issue21's "Suballocation alignment" row instructs a literal
`VmaVirtualAllocationCreateInfo::alignment = 48` — INVALID: VMA requires
power-of-two alignment (documented in the vendored header) and silently
corrupts offsets otherwise (`VmaAlignUp(240,48) = 272`, reproduced
independently by implementer and reviewer). Binding correction: pools
suballocate in ELEMENT UNITS (element-count allocations with
`alignment = 0`; byte addressing derived at upload/bind time), which
satisfies D9's real intent (offsets convert exactly to
`vertexOffset`/`firstIndex`) by construction. Do not copy the matrix's
literal byte-alignment wording into any future task.

**Errata E2 (2026-08-20, #29 executor allocations).** The
matrix-issue29 site-1-2 row's justification that a capacity-only
signal for the three `std::vector<bool>` tracking fields is "not a
realistic false-negative risk" is EMPIRICALLY FALSIFIED: both the
implementer's and the independent reviewer's revert probes confirmed
a "freshly reconstruct to identical final size" regression passes the
capacity-only check (std::vector<bool> exposes no .data() for
pointer-identity). The binding criterion's SHAPE stands as delivered
(the row binds both the vector<bool> type and the capacity-only test;
switching types would violate the row as written) — the gap is
ACCEPTED and documented in task-23-report.md. Any future rework of
these fields must either preserve this documented limitation
explicitly or move to a pointer-identity-capable type WITH a matrix
amendment.
